OPEN STANDARDS

STIX 2.1 Architecture: SDOs, SCOs & SROs

OASIS Structured Threat Information Expression: JSON graph serialization of threat intelligence.

SDOs (Domain Objects)

The conceptual building blocks

  • threat-actor (UNC-PHOENIX)
  • attack-pattern (T1059.001)
  • indicator (Pattern match)
  • malware (BlackCat)
  • identity (Victim Org)
SCOs (Cyber Observables)

The technical empirical facts

  • ipv4-addr (198.51.100.45)
  • domain-name (internal-sync.com)
  • file (SHA-256 hash)
  • network-traffic (TLS port 443)
  • user-account (Compromised ID)
SROs (Relationship Objects)

The connective glue

  • relationship (uses, indicates, targets)
  • sighting (internal empirical detection)
  • Connects source_ref ➔ target_ref
  • Enables graph visualization!
[SAY:] STIX 2.1 is the universal language of threat sharing. Why do we need it? Imagine a college lab where every student writes code in a different format: one in Python, one on a ruled sheet, one in Malayalam, and one carved on the desk! The external examiner would reject everything. STIX 2.1 standardizes SDOs, SCOs, and SROs into clean JSON that every machine can parse. [PEDAGOGY:] HUMOR ANCHOR: Submitting lab records in 4 different handwriting formats vs. standard JSON. Walk through the 3 core STIX object types.

SCORING ALGORITHM

Contextual Indicator Scoring: Beyond Raw Reputation

Calculating composite confidence from multiple weighted intelligence dimensions.

DIMENSION 1: SOURCE PEDIGREE

NATO Admiralty Reliability score. Government DFIR bulletin (B) carries vastly greater weight than anonymous pastebins (E/F).

Weight: 35% of composite
DIMENSION 2: RECENCY & AGING

First observed vs. Last observed. Indicators decay rapidly: confidence degrades 50% after 14 days without active C2 telemetry.

Weight: 30% of composite
DIMENSION 3: SIGHTINGS & CONTEXT

Corroborating sightings in internal SIEM logs or sandbox detonation traces. Multi-source sightings eliminate false positives.

Weight: 35% of composite
[SAY:] Never rely on a single vendor's reputation score. We calculate a composite score: 35% source pedigree, 30% recency, and 35% internal sightings. That is how enterprise SOCs avoid blocking benign infrastructure. [PEDAGOGY:] Walk through the 3-part composite scoring formula.

TRAINER DEMONSTRATION

Demo 3: Programmatic STIX 2.1 Generation via Python

Creating verified SDOs, SCOs, and SROs using the official stix2 Python SDK.

generate_stix_bundle.py // PYTHON 3.11
# Import official OASIS stix2 library: from stix2 import ThreatActor, Indicator, Relationship, Bundle # 1. Define Threat Actor SDO: actor = ThreatActor(name="UNC-PHOENIX", threat_actor_types=["cybercrime"]) # 2. Define Indicator SDO with STIX Pattern: indicator = Indicator(indicator_types=["malicious-activity"], pattern="[ipv4-addr:value = '198.51.100.45']", pattern_type="stix") # 3. Connect via SRO Relationship: rel = Relationship(source_ref=indicator.id, relationship_type="indicates", target_ref=actor.id) # 4. Export Validated Bundle: bundle = Bundle(objects=[actor, indicator, rel]) print(bundle.serialize(pretty=True))
