EVIDENCE PRESERVATION

RFC 3227: Order of Volatility & Legal Chain of Custody

Evidence disappears at different rates. Capture the most volatile artifacts first.

1. CPU Registers & Cache NANOSECONDS
Vanishes instantly on context switch. Rarely captured in standard enterprise triage.
2. Routing Tables, ARP Cache, Process Table, Kernel Memory (RAM) SECONDS TO MINUTES
Decrypted malware binaries, active C2 network sockets, injected DLLs, unencrypted keys. Vulnerable to power loss!
3. Temporary File Systems & Swap Space MINUTES TO HOURS
Virtual memory pagefile.sys, hiberfil.sys, staging folders (C:\Windows\Temp).
4. Non-Volatile Storage (Hard Disks, SSDs) & Remote Logging DAYS TO YEARS
NTFS $MFT, Event Log EVTX files, prefetch, Amcache. Stable across power cycles.
[SAY:] RFC 3227 dictates our preservation sequence. Notice RAM sits at Level 2. If you turn off the power, volatile RAM vanishes forever. Always capture memory before touching the hard drive. [PEDAGOGY:] Drill the RFC 3227 order of volatility into memory. Direct bridge to the Golden Rule.
FORENSIC CARDINAL SIN

The Golden Rule of Incident Response: Do Not Reboot!

Rebooting an infected system destroys the most critical evidence required for attribution.

WHAT REBOOTING DESTROYS FOREVER:
  • Volatile RAM: Injected fileless malware DLLs running in memory.
  • Decrypted Payloads: Ransomware keys stored in memory buffers.
  • Active Network Sockets: Live TCP connections to adversary C2 IP nodes.
  • Running Process Tree: Parent-child process IDs and command lines.
  • Logged-in Session Tokens: Stolen Kerberos tickets and NTLM hashes.
CORRECT TRIAGE PROTOCOL:
  • 1. Network Isolation: Disconnect Ethernet or apply host firewall null-route.
  • 2. Keep Power On: Prevent system shutdown or sleep mode.
  • 3. Live Memory Dump: Execute WinPmem, DumpIt, or LiME memory acquisition.
  • 4. Triage Collection: Run KAPE to extract $MFT, Prefetch, and Event Logs.
  • 5. Chain of Custody: Calculate SHA-256 hash immediately on extraction!
[SAY:] When your laptop starts behaving strangely, the common campus instinct is: 'Sir, just restart it and hope the problem has graduated and left!' In incident response, restarting the machine is an unforgivable forensic crime! Rebooting dumps volatile RAM instantly—which is where the malware's decrypted payload and active C2 sockets live. It is like a detective arriving at a crime scene with a mop and disinfectant and washing the floor before taking fingerprints! [PEDAGOGY:] HUMOR ANCHOR: The detective arriving at a crime scene with a mop and disinfectant! The classic 'problem graduated' joke. Unforgettable forensic lesson.

RAPID TRIAGE

KAPE: Kroll Artifact Parser and Extractor

Eric Zimmerman's triage tool acquires 95% of forensic value in under 5 minutes.

TARGETS (--targets)

Specifies WHAT files to copy

  • KapeTriage: Compound target collection
  • $MFT: Master File Table metadata
  • RegistryHives: SYSTEM, SOFTWARE, SAM, NTUSER.dat
  • EventLogs: All *.evtx operational logs
  • Prefetch: Evidence of program execution
MODULES (--modules)

Specifies HOW to parse artifacts

  • MFTECmd: Parses $MFT into CSV timeline
  • PECmd: Parses Prefetch execution run counts
  • EvtxECmd: Parses and normalizes Event Logs
  • RECmd: Extracts registry persistence keys
  • Outputs normalized CSV for Timeline Explorer!
[SAY:] In the old days of forensics, capturing an image of a 2 TB hard drive took 14 hours. In incident response, you don't have 14 hours! KAPE copies only the forensic crown jewels: the MFT, prefetch, registry, and event logs. It finishes in 4 minutes and gives you 95% of the evidence. [PEDAGOGY:] Contrast full physical bitstream imaging with surgical forensic triage via KAPE.
ANTI-FORENSICS EXPOSED

Timestomping: $STANDARD_INFORMATION vs. $FILE_NAME

Adversaries modify file timestamps to blend in with legitimate system software.

The NTFS Dual-Timestamp Mechanism:
• $STANDARD_INFORMATION ($SI): The timestamp shown in Windows Explorer. User-mode APIs can freely backdate this attribute.
• $FILE_NAME ($FN): The kernel-level timestamp recorded when the file name is created/renamed. Only the Windows operating system kernel can update this attribute!
TIMELINE EXPLORER // ANOMALY EXPOSED
File Name: C:\Windows\Temp\calc_updater.exe $SI Created: 2021-04-12 08:14:02 (Falsified!) $FN Created: 2026-10-30 02:14:15 (REAL KERNEL RECEIPT!)
VERDICT: TIMESTOMPED MALWARE (UNC-PHOENIX)
[SAY:] Adversaries try to hide by modifying file timestamps—timestomping. They take their malware and change its creation date to match calc.exe from 2021. It's like a student who forgot to submit an assignment on Monday, so they change the date on the front page to 'Last Friday' and hope the professor doesn't notice! But NTFS keeps two receipts: $STANDARD_INFORMATION and $FILE_NAME. When we compare them in Timeline Explorer, the lie is exposed instantly! [PEDAGOGY:] HUMOR ANCHOR: Backdating an assignment submission to last Friday! Explains why $FILE_NAME kernel timestamps catch anti-forensics.

LAB-06: STEP 6 OF 7 // ERROR RESOLUTION & RECOVERY

Common Triage Mistakes & Recovery

Correcting timestamp inversion bugs and evidence custody record omissions.

Issue 1: Chronological Inversion Caused by Local Timezone Offsets

Occurs if logs recorded in IST (+5:30) are sorted alphabetically against UTC logs.

# Recovery: In Excel/Python, convert all timestamps to ISO-8601 UTC datetime.fromisoformat('2026-10-26T19:42:05+05:30').astimezone(timezone.utc)
Issue 2: Verification Hash Mismatch on Raw Evidence Image

Occurs if evidence file was mounted or modified during initial analysis.

# Golden Forensic Rule: NEVER analyze live evidence # Recovery: Make a working copy -> work ONLY on working copy! Copy-Item "EVD-001.raw" "EVD-001_working.raw" -ReadOnly
[SAY:] Never analyze original evidence directly. If you modify a single byte or change a file access timestamp, you break the hash and invalidate the evidence. [PEDAGOGY:] Reinforce RFC 3227 Order of Volatility and the golden rule: work only on forensic clones.
